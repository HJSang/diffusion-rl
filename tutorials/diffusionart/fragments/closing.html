Putting it together

The whole method fits on one screen once the pieces are in place. Use this section as a review sheet and a self-test.

The argument in eight sentences

  1. A rectified-flow model generates by integrating a learned velocity field from noise ($t=1$) to data ($t=0$), and it is trained by regressing the per-sample target $u_t=x_0-\epsilon$.
  2. RL fine-tuning treats each sampler step as an action and scores only the final sample, so one scalar must be spread over many steps.
  3. Reverse-process RL (Flow-GRPO) turns the ODE into an SDE to get step likelihoods, then pushes each step along its own sampled noise, scaled by a trajectory-level advantage. That is noisy credit assignment.
  4. Forward-process RL (DiffusionNFT) re-noises endpoints and regresses velocities toward reward-weighted targets. It needs no likelihoods and learns fast, but each branch alone collapses and the joint version needs a tuned EMA.
  5. The reason: NFT's targets assume the model's sampling velocity equals the ideal forward velocity of its own endpoints. The gap between the two adds a force unrelated to reward that the two branches only partly cancel.
  6. EMA helps because the lagged model pulls the trainable one back (restoration), not because the data is off-policy.
  7. DiffusionART instead aggregates each prompt's $K$ endpoints and rewards into one direction, $G(c)\propto\operatorname{Cov}(R,x_0)$, which is the first-order effect of tilting $p_{\text{old}}$ by $e^{\tau R}$, and adds it to the cached velocity at every visited state. No forward velocity appears, so the consistency force is gone by construction.
  8. Two disjoint MSE updates toward the same frozen target make the second update contain a restoration term $-d(s_t)$ proportional to each state's drift, and a KL-proxy mask stops outward drift beyond a threshold.

Self-test

You are ready to work on this area when you can answer these without notes.

Why can DiffusionART sample with a deterministic ODE when Flow-GRPO cannot?

Flow-GRPO's objective is a likelihood ratio of sampler steps, and a deterministic step has no density, so it must inject noise (SDE). DiffusionART's loss is a velocity regression toward a frozen target, which needs no step likelihood. It borrows the SDE only as a reference to measure drift in the trust-region mask, and the rollout itself stays an ODE.

What does $G(c)$ become when all $K$ rewards for a prompt are equal, and what does the update do then?

The covariance is zero, so there is no reward signal for that prompt. Step 5 traces how the code guards the RMS normalization in this case. With a zero guidance the target equals the cached velocity, so the first update has zero loss on those states and the second update only restores drift toward $v_\theta^{(0)}$.

Why does the second update restore, while the first does not?

Before the first update $v_\theta=v_\theta^{(0)}$, so the residual to the target is exactly $G(c)$. After it, the model has moved by $d(s_t)$ and the residual is $G(c)-d(s_t)$; the $-d(s_t)$ part pulls each state back in proportion to how far it drifted, which is the restoration force EMA provided in NFT.

In one sentence, what is the forward–reverse consistency force?

It is the part of NFT's update that moves the model's sampling velocity toward (positive branch) or away from (negative branch) the ideal forward velocity induced by its own endpoints. That gap has nothing to do with reward, and centered rewards cancel it across samples but not at each state.

Name two settings where you would expect DiffusionART's advantage to shrink, and why.

Examples: (1) rewards whose improvement direction differs strongly between noise levels or between regions of a prompt's sample space, because one shared $G(c)$ per prompt is a first-order, mean-shift signal; (2) very small $K$ with scalar rewards, where the covariance estimate is noisy (the paper's pairwise results with $K=2$ are the counterpoint to test). Step 4's critical-reading section lists more.
